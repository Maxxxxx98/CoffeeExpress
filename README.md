# ☕ CoffeeExpress

### Вебсистема онлайн-замовлень у кав'ярні

**Швидке оформлення попередніх замовлень кави та десертів без черг**

---

## 📌 Про проєкт

**CoffeeExpress** — це швидкий, клієнт-серверний вебзастосунок, розроблений для автоматизації процесу замовлень у кав'ярнях, скорочення часу очікування відвідувачів у години пік та уникнення живих черг.

Клієнти мають можливість переглядати меню, налаштовувати напої (вибір молока, сиропу, розміру) у реальному часі та замовляти їх на точний час самовивозу прямо у браузері без необхідності встановлення окремих додатків. Персонал кав'ярні (бариста) отримує ергономічне робоче місце для відстеження та зміни статусів замовлень.

---

## 🚀 Особливості системи

* 📱 **Адаптивна вітрина (Front-end):** сучасний чуйний інтерфейс на базі Bootstrap 5 та спеціальної кавової дизайн-системи.


* ☕ **Інтерактивний кастомізатор:** вибір розміру чашки (M/L), виду молока (звичайне, безлактозне, вівсяне, мигдальне) та сиропів із синхронним перерахунком суми «на льоту».


* 🛒 **Швидкий кошик (Single Page Application):** керування замовленням без перезавантаження сторінки через Vanilla JS (ES6+).


* 🔒 **Робоче місце баристи (`/admin`):** захищена панель моніторингу замовлень із підтримкою автоматичного оновлення (long polling) та переведенням статусів («Нове» → «Готується» → «Готове» → «Видано»).


* ⚡ **Висока швидкодія:** час відгуку сервера (TTFB) менше 5 мс, швидка робота з базою даних SQLite без зайвих витрат ресурсів.

## 🏛 Архітектура системи

Проєкт реалізовано за трирівневою клієнт-серверною архітектурою:

Клієнтський браузер (User / Admin)
│
▼  HTTP/1.1 (JSON, Fetch API)
Вебсервер & REST API (Python Flask)
├── Валідація даних (Regex, Type Checks)
├── Аутентифікація сесій (@login_required)
└── Модуль БД (database.py, context managers)
│
▼  SQL-запити (PRAGMA foreign_keys = ON)
Реляційне сховище (SQLite3: instance/coffee.db)

## 🔌 Специфікація Back-end REST API

Усі маршрути обмінюються даними у кодуванні UTF-8 та форматі application/json. Базовий префікс: /api.

| Метод | Ендпоїнт | Доступ | Опис | Коди HTTP |
| --- | --- | --- | --- | --- |
| GET | /api/products | Публічний | Отримання каталогу актуального меню кав'ярні | 200 OK, 500 Internal Server Error

 |
| POST | /api/orders | Публічний | Реєстрація нового замовлення з валідацією | 201 Created, 400 Bad Request

 |
| GET | /api/orders | Тільки персонал | Отримання журналу всіх замовлень | 200 OK, 401 Unauthorized

 |
| PATCH | /api/orders//status | Тільки персонал | Оновлення статусу замовлення | 200 OK, 400 Bad Request, 404 Not Found

 |
| POST | /api/auth/login | Публічний | Авторизація персоналу (створення сесії) | 200 OK, 401 Unauthorized

 |
| POST | /api/auth/logout | Авторизований | Завершення сесії персоналу | 200 OK

 |

### Приклад створення замовлення (POST /api/orders)

Тіло запиту:
{
"customer_name": "Олексій Іваненко",
"customer_phone": "+380671112233",
"pickup_time": "14:30",
"items": [
{
"id": 2,

"price": 90.0,

}

{

"order_id": 1,

## ⚙️ Інструкція з налаштування та локального запуску

### Системні вимоги:

* Інтерпретатор Python 3.10 або вище
* Менеджер пакетів pip
* Система контролю версій Git

### Покроковий алгоритм запуску:

1. Клонувати репозиторій з GitHub:
git clone [https://github.com/Maxxxxx98/CoffeeExpress.git](https://github.com/Maxxxxx98/CoffeeExpress.git?utm_source=gemini)
cd CoffeeExpress
2. Створити та активувати віртуальне середовище:
Windows:
python -m venv venv
.\venv\Scripts\activate

Linux / macOS:
python3 -m venv venv
source venv/bin/activate

3. Встановити залежності проєкту:
pip install --upgrade pip
pip install -r requirements.txt
4. Запустити сервер застосунку:
python app.py

(Під час першого запуску база даних instance/coffee.db створиться та заповниться початковим меню автоматично).

5. Відкрити вебзастосунок у браузері:

* Клієнтська вітрина замовлень: [http://127.0.0.1:5000/](https://www.google.com/search?q=http://127.0.0.1:5000/&utm_source=gemini)
* Робоче місце баристи: [http://127.0.0.1:5000/admin](http://127.0.0.1:5000/admin?utm_source=gemini) (Логін: admin, Пароль: coffee2026)

## 🧪 Автоматизоване тестування

Для перевірки коректності бізнес-логіки та захисту ендпоїнтів реалізовано тестовий набір на базі фреймворку pytest за патерном Arrange-Act-Assert:

pytest test_app.py -v

Покриття тестів включає:

1. test_fetch_products_catalog — отримання каталогу товарів (200 OK).


2. test_create_order_success — успішне створення замовлення (201 Created).


3. test_create_order_invalid_phone — валідація мобільного номера (400 Bad Request).


4. test_create_order_empty_cart — блокування замовлення з порожнім кошиком (400 Bad Request).


5. test_admin_orders_unauthorized_access — захист панелі баристи від неавторизованого входу (401 Unauthorized).


6. test_admin_authentication_and_status_update — наскрізний тест авторизації та оновлення статусу замовлення.

## 🔐 Безпека та валідація даних

* Захист від ін'єкцій: усі операції в database.py виконуються через параметризовані SQL-запити (cursor.execute), що повністю унеможливлює SQL-ін'єкції.
* Строга валідація вхідних даних: перевірка формату номерів телефонів за допомогою Regex, захист від від'ємних цін і пустих кошиків[cite: 4, 5].
* Сесійний захист адміністративної панелі: використання декоратора @login_required із підписаними сесійними cookie-файлами Flask.


* Контекстні менеджери: гарантують автоматичне закриття з'єднань із базою даних і відкат (rollback) транзакцій у разі збоїв.
